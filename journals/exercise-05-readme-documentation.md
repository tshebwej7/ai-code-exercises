# Exercise 5 — README Documentation

## Objective

The objective of this exercise was to use AI to create comprehensive project documentation for the Task Manager CLI.

The documentation needed to explain the project to developers and users who were unfamiliar with the application.

---

# Project Selected

**Project:** Task Manager CLI

**Language:** JavaScript

**Location:**

`use-cases/code-algorithms/javascript/TaskManager/`

---

# Part 1 — Comprehensive README

The README was expanded to document:

- project purpose;
- features;
- prerequisites;
- installation;
- running the application;
- available commands;
- command options;
- examples;
- testing;
- test coverage;
- data storage;
- task priorities;
- task statuses;
- FAQ.

The documentation was based on the existing project README and the documented behavior of the Task Manager.

---

# Part 2 — Step-by-Step Feature Guide

The selected feature was the basic task-management workflow.

The guide demonstrates how a user can:

1. Create a task.
2. View the task.
3. Change its status.
4. Add a tag.
5. Change its priority.
6. Mark it as completed.
7. View task statistics.

This provides a practical sequence rather than documenting individual commands in isolation.

The README includes ten frequently asked questions covering:

---

# AI Documentation Approach

AI was used to structure and expand the existing documentation.

The important part of the process was verifying the generated documentation against the source material rather than assuming that every generated statement was correct.

The existing project README was treated as the source of documented behavior.

---

# Key Learning

The exercise demonstrated that good project documentation needs to serve different audiences.

A README should provide a quick understanding of the project and explain how to get started.

A feature guide should help a user complete a real workflow.

An FAQ should answer common questions without requiring the user to search through the entire README.

---

# Reflection

One of the main challenges was deciding how much information to include.

Too little documentation would leave new users unable to understand the project.

Too much unsupported information could introduce incorrect assumptions.

The best approach was therefore to organize and expand the information that was actually supported by the project documentation.

Another important lesson was that AI-generated documentation still requires human verification.

AI can organize information quickly, but the developer remains responsible for ensuring that the documentation accurately represents the software.
